## 已实现的行为

- 每日参数、短期计划与自然语言任务统一通过后台 `plan_work()` 生成。游戏执行流程不再等待模型回复。
- 同时最多一个模型请求；后台只接收文字状态副本，不持有游戏连接。
- 模型一次生成最多 6 个步骤；自主队列剩一项且达到补充间隔时，提前请求下一段。
- 模型仍在思考或请求失败时，按当前体力、物资和已有当日参数继续可执行农务。
- 收获、浇水、播种、清障每段最多 3 格；模型任务未完成时，保留剩余工作继续执行。砍树每段最多挥工具 3 次。
- 每段完成后观察最新状态，跳过已完成或不满足条件的旧步骤。
- 有进展时约 0.1 秒后继续；没有可执行任务时等待 2 秒，异常时等待 5 秒。取消固定约 30 秒空档。
- 模型失败按 15～120 秒退避；农务目标失败时按坐标记录历史并换目标；整项技能受阻时冷却 30 秒。详见 `docs/action-history.md`。
- 使用年份、季节、日号和存档会话识别旧计划；玩家新指令也会使旧规划失效。
- 状态文件增加 `planner.thinking` 和 `planner.queued_steps`，日志记录模型请求、结果耗时与执行来源。

## 使用方式与边界

原来的启动方式继续可用。运行中的旧服务需要先正常停止，再重新启动，以加载修改后的代码。

也可在仓库目录执行：

```powershell
python bot\farm_service.py --loop
```

无需新增 Python 依赖，也无需重新编译 Mod。

`--once` 现在只做一段当前可执行农务，后台模型结果需要在 `--loop` 的后续轮次中接收。
新任务会替换未完成的旧任务；模型思考期间仍按当前默认农务或已有当日设置工作。
这次实现没有新增用户保护区域、资源保留清单或对尚未解析的自然语言限制的即时识别。

采购往返、回家睡觉与节日保留原有完整技能流程；新计划和停止指令在技能边界检查。
停止后不会继续派发游戏动作，但在途 HTTP 线程可能需要等网络超时才能结束进程。
确实没有可执行目标时，程序会等待状态变化，不会为保持忙碌而无限重复无进展动作。
