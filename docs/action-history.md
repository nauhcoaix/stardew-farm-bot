## 现在的行为

1. 每个农务目标拥有标签，例如 `till@Farm:66,21`，另有包含游戏会话和日期的短 ID。
2. 记录 `done`（完成）、`progress`（有效砍树一击）、`failed`（报错）、`no_progress`（返回成功但目标没变化）。
3. 普通失败首次出现就跳过该目标，继续其他地块或技能。不会因重新规划、角色移动、时间推进、体力变化或 ref 更新而再次尝试同一个未改变的目标。
4. `STALE_REF/BUSY/TRANSITION` 最少等待 2 秒后允许一次重试；仍失败则停止重试，等待目标状态变化。如果整个技能也进入冷却，实际重试会更晚。
5. 目标的地块/作物状态变化，或跨日、存档会话变化时重新评估。正常浇下一格、收下一株及 Mod 验证成功的连续砍树仍可重复。
6. 移动和选择工具后按坐标重新获取当前 ref；分段中后续地块也使用最新引用。
7. 服务按经过验证的农务计数判断进展。仅消耗体力、水量，或只是移动和刷新视野，不算完成工作。
8. 本地策略、模型队列与实际执行共用历史。模型的下一次请求会带上最近结果及受阻目标。

历史保存在 `FARM_DATA/action-history.json`，未配置 `FARM_DATA` 时为 `bot/action-history.json`；使用临时文件替换保存。同一游戏会话和日期内重启 Python 服务后仍保留。换游戏会话或日期会清掉旧目标记录，近期明细最多保留 24 条。运行历史已加入 `.gitignore`。

## 实现文件

- `bot/action_history.py`：目标身份、状态比较、失败过滤、持久化、模型摘要。
- `bot/farmer.py`：统一目标执行入口，验证结果后更新计数与历史。
- `bot/farm_service.py`：选择工作前过滤受阻目标，修正进展判断，注入共享历史。
- `bot/work_planner.py`：跨轮次持有历史；存在其他目标时不冷却整个技能。
- `bot/planner.py`：增加历史标签说明。
- `tests/test_action_history.py`：10 项新的离线回归测试。
