# 清障策略（为什么不再乱清）

## 以前为什么乱清

模型只输出一个数量：

```json
{ "clear_limit": 8, "clear_min_energy": 60 }
```

执行层就按「杂草优先 + 离自己近」清 8 个 —— **不管农场缺不缺地**。
模型也没法判断：它只知道「第 8 天 春 · 体力 258/270 · 作物 0 株」，不知道自己在哪、
哪片是开垦区、还缺几格能种。所以清障变成「有杂草就清」。

## 现在的规则

### 1. 缺口驱动

```
可用 = 已翻地空着的格子 + 可耕地
缺口 = 想种的格数 - 可用

缺口 <= 0  →  一个都不清
缺口 > 0   →  只清「能变成耕地、且在开垦区内」的那几格
```

计划里的字段：`plant_target`（今天想种几格）。

### 2. 区域闸门（`clear_zone`）

| 值 | 允许清的范围 | 什么时候用 |
|---|---|---|
| `none` | 不清 | 地够种（默认会自己变成这个） |
| `cluster` | **开垦区内部 + 外扩 1 格** | 缺地时的默认值 |
| `path` | 挡在去 宝箱/水源/农舍/出口 路上的 | 路被堵死时 |
| `all` | 全农场 | 大规模开荒，平时不用 |

农业边角、路边、树底下的杂草，**种不到那里，永远不清**。

### 3. 每日预算

```
FARM_CLEAR_BUDGET=20      # 每天最多清 20 格，用完就停
```

### 4. 模型能看见方位（地图摘要）

`refresh_plan` 发给模型的不再是一行状态，而是：

```
第8天 春 1050点，体力 258/270，钱 240，种子 6，作物 18 株，背包 7/36，木材 14

你在：农舍东南约 12 格，开垦区里（坐标 64,18）
农场统计：可耕地 27 格，已翻地 15 格，其中空着能直接种 13 格，作物 2 格，障碍 48 个（开垦区内 2 个）
分区：I3(地9/苗9/障1)；H3(地6/苗2/障1)；F2(地0/苗0/障1)
地图（@你 c作物 t空地 .可耕地 #障碍 w水 b箱子 H农舍）：
      H
     b
     c@t
    wttt
```

模型据此判断「够不够种」，而不是拍一个 `clear_limit`。

### 5. 两种模式

| 模式 | 行为 |
|---|---|
| `FARM_CLEAR_MODE=auto`（默认） | 代码按缺口 + 区域自己算，模型只决定种多少 |
| `FARM_CLEAR_MODE=ask` | 代码把候选清单（带理由和体力代价）交给模型，模型挑编号 |

`ask` 模式的候选长这样：

```
想种 10 格，能直接种 4 格，缺 6 格。候选：
1. 杂草 在 (65,20)：在开垦区内，清完能种，体力 0
2. 嫩枝 在 (62,21)：在开垦区内，清完能种，体力 2
3. 杂草 在 (40,8)：开荒（区外没用），体力 0
```

模型只输出 `{"clear": [1,2]}` —— 选择题比开放题稳。

### 6. 日志与统计

每轮一行：

```
[清障] zone=cluster 目标=10 可用=4 缺口=6 预算剩=20 理由=缺6格地
[清障] 清了 4 格（区内 4 / 区外 0），今天累计 4/20
```

日终汇总里带 `DAY_CLEAR`：清了多少、区内多少、区外多少。

**评估指标**（一周后看）：

```
清理格数 / 实际种上格数     越接近 1 越好
清在开垦区外的比例           越接近 0 越好
```

## 涉及的文件

```
bot/farm_layout.py   地图摘要 + 候选生成 + 区域判定（纯计算，可单测）
bot/farmer.py        clear_obstacles(zone=, need=, picks=) 按候选执行
bot/planner.py       prompt 加地图/缺口/clear_zone；pick_candidates() 选择题
bot/farm_service.py  auto_clear()：算缺口 → 定 zone → 预算 → 执行/让模型挑
```
