# 学习行为验收（evals）

本目录只放**脱敏的验收协议与格式**，不含个人存档、密钥或真实运行结果。
代码层面的 `pytest` 全绿只能证明“接口接通”，不能证明“学会了”。

## 分组

每个核心场景至少三组**配对**试验：

| 组 | 准备 | 允许的行为 |
|---|---|---|
| 经验组（treatment） | 载入固定版本的训练经历与已验证组合技能 | 观察、临时记忆、检索、复用 |
| 禁用经验组（control） | 清空经历、已验证组合、地图缓存与跨存档迁移经验 | 使用相同基本动作、接口说明与模型配置 |

两组使用同一份测试存档副本、同一模型版本、同一提示词、同一工具集合、同一预算；
随机性与服务延迟如实记录；交替两组运行顺序。

不能只清“文字检索”却让对照组继续调用已学组合技能。

## 实时约束

两组都按实时条件运行：推理期间游戏继续，不因某组较慢而暂停补偿。
实际用时、请求数、tokens、失败与无进展次数、资源损失都要记录。

## 判据

主指标：任务开始到**验证完成**的墙钟时间（失败按该次运行的完整时间预算计入），
比较两组中位数。

已确认门槛：

- 每个核心场景 ≥ 3 组配对试验；
- 重启后至少 2/3 次完成经验复用；
- 有“条件变化纠错”场景：执行前识别不适用，或收到失败证据后停止原方案并重新决策；
- 预先选定的效率或失败次数指标有改善；没有改善只能报告“功能接通”，不能报告“学习有效”。

任务开始前固定预算与指标，不在看到结果后改口径。

## 场景文件

| 文件 | 目标 | 不允许的替代证明 |
|---|---|---|
| `scenarios/farm_basic.json` | 在指定区域种下三颗指定种子并浇水 | 模型说完成、接口返回 completed、次日只看到作物 |
| `scenarios/inventory_relief.json` | 保留指定物品、恢复收集空间并实际继续收集 | 丢弃/卖掉保护物品、只报告空槽、场景实际无解 |
| `scenarios/premise_change.json` | 关键前提变化后停止原方案并重新决策 | 无变化重复同一失败、假称成功、调试传送补救 |

验收不向模型注入答案；评价者可以持有解法，机器人上下文不得获得。

## 报告

`report.schema.json` 定义一个报告文件的结构：`scenarios[].runs[]` 每次尝试一条，
包括 `group`、`started_at`、`wall_clock_seconds`、`verified`、`failure_reason`、
`model_requests`、`tokens`、`no_progress_actions`、`resource_loss`、`evidence_refs`
与 `notes`。`attempts` 必须保留失败记录。可用 `python -m stardew_agent export`
导出证据，再人工/脚本裁剪成本格式。

## 尚不可声称

- 本轮没有执行任何实机试验，`evals/results/` 为空；
- 三组配对只是工程验收，不能据此声称统计上普遍有效；
- 预制钓鱼控制、游戏已有配方显示、模型已有常识等来源必须单独标注，
  不能包装成“项目教授的发现”。
