# 叠加层（HUD）与并行预取

日期：2026-10-26

## 现状问题

模型一次请求可能要 3～30 秒，而一个动作只要 1～3 秒。旧流程是「取一个动作 → 执行 → 队列空了再问模型」，
于是执行器经常停下来等模型，表现为"人不动，日志一直在后台规划"。

## 这次做的两件事

### 1）窗口叠加层（AgentStardew 桥 0.2.0）

- 新增桥命令：`hud {title, lines[], ttlMs}`，在 `Display.RenderedHud` 里画左上角面板；
- 面板内容：`下一步动作 + 参数`、`目标`、`剩余 N 步 · 是否在后台规划`、最近 5 条记忆（技能结果 / 计划 / 笔记）；
- 超时自动消失（默认 60 秒），绘制异常只关掉自己，不影响游戏；
- 位置按 `Game1.uiViewport` 原点换算 —— 该原点常为负数（画面放大/居中），直接画 `(12,12)` 会落在屏幕外；
- 诊断：`Mods/AgentStardew/runtime/hud-diag.log` 记录「set / draw called / drawn at x,y / error」。

Python 侧 `bot/hud.py` 负责组装文本；`ObservedBridge` 把 `hud` 当直通命令，不额外拍快照、不写记忆事件。

### 2）并行预取（执行不停，规划在后）

- `WorkPlanner.prefetch()`：队列余量 ≤2 步时就发起下一次模型请求，不再等队列见底；
- `farm_service._run_once()` 在**派发动作之后、执行动作之前**调用 `prefetch()`，让模型思考和游戏动作真正重叠；
- 单次规划上限 6 → 12 步（`skill_catalog.clean_steps` 与提示词同步），少问几次、多跑几步；
- 仍是"同时最多一个在途请求"，失败/跨日/新指令仍会作废旧结果（`revision` 语义不变）。

## 边界

- HUD 只是显示层：不改游戏状态、不注入输入、不改变任何动作判定；
- 桥不支持 `hud` 时（旧版本）Python 侧只提示一次并永久关闭，不影响主循环；
- 旧桥仍可用，只是没有叠加层。

## 验证

```
桥 0.2.0 加载 → hello.capabilities 含 hud
hud 命令 → {"kind":"hud","lines":5}
窗口抓屏 → 面板确实显示「下一步动作 / 目标 / 剩余步数 / 记忆条目」
farm_service --once → 实际推送「等待模型选技能 …」
仓库测试 57 项通过
```
